#### 2.2 Линейный поиск и проверка простоты

Функция `linear_search` просматривает список слева направо и возвращает индекс первого вхождения и число выполненных сравнений; если число отсутствует, возвращается `-1`. #### 2.3 Сложность алгоритмов

**Таблица 3 – Сложность реализованных алгоритмов**

| Алгоритм | Время | Дополнительная память | От чего зависит число операций |
|---|---|---|---|
| Один проход (сумма, минимум, максимум, четные) | O(n) | O(1) | длина списка n |
| Второй проход (больше среднего) | O(n) | O(1) | длина списка n |
| Линейный поиск | O(n), в лучшем случае O(1) | O(1) | позиция искомого элемента, n |
| Проверка простоты | O(√n) | O(1) | величина числа n |
| Сортировка выбором | O(n²) | O(1) (O(n) для копии) | длина списка n |
| Бинарный поиск | O(log n) | O(1) | длина отсортированного списка n |

Почему ограничение делителей квадратным корнем корректно. Если составное число n = a · b и a ≤ b, то a² ≤ a · b = n, то есть меньший из делителей не превосходит √n. Поэтому у составного числа всегда есть делитель от 2 до √n включительно, и если такого делителя нет, число простое. Включительная граница нужна для квадратов простых чисел: у 25 единственный делитель в диапазоне – 5 = √25. Условие `d * d <= n` проверяет границу в целых числах без погрешностей вещественного корня. Для n = 1 000 003 проверено только 999 делителей вместо миллиона.



#### 2.4 Практическое расширение: сортировка выбором и бинарный поиск

Сортировка выбором реализована функцией `selection_sort` (число сравнений n(n − 1)/2), бинарный поиск – функцией `binary_search`. Бинарный поиск выполняет на каждой итерации сравнение на равенство и сравнение «меньше»; каждое из них считается одним сравнением. Линейный поиск считает одно сравнение на элемент. Алгоритмы запущены на одинаковых наборах из 10, 100 и 1000 различных чисел; для каждого набора определены число сравнений в худшем случае (искомого числа в наборе нет) и среднее число сравнений по всем элементам набора (таблица 4).

**Таблица 4 – Число сравнений при поиске**

| n | Линейный, худший случай | Линейный, среднее | Бинарный, худший случай | Бинарный, среднее |
|---|---|---|---|---|
| 10 | 10 | 5,5 | 6 | 4,8 |
| 100 | 100 | 50,5 | 12 | 10,6 |
| 1000 | 1000 | 500,5 | 18 | 17,0 |

Число сравнений линейного поиска растет пропорционально n (худший случай n, среднее (n + 1)/2), бинарного – логарифмически: при росте n в 10 раз оно увеличивается примерно на 6 сравнений (на 3 шага по два сравнения). Цена бинарного поиска – необходимость предварительной сортировки: сортировка выбором требует O(n²) сравнений, поэтому для однократного поиска линейный алгоритм выгоднее.

### 3 Задание 3. Коллекции и выбор структуры данных

#### 3.1 Решение

Данные о сдаче работ хранятся в пяти структурах, которые строятся единым проходом функцией `build_structures`:

- `students` – множество всех студентов;
- `labs` – множество всех сданных лабораторных работ;
- `attempts` – словарь «студент → список попыток (работа, результат)»;
- `best` – словарь лучших результатов по ключу `(student, lab)`;
- `count` – словарь числа попыток по ключу `(student, lab)`.

Студенты, сдавшие обе работы, определяются пересечением множеств: для каждой работы строится множество сдавших ее студентов, затем множество всех студентов последовательно пересекается с ними (`&=`). Исходные данные дают `anna` и `boris`. Функция `add_submission` обновляет все пять структур одной записи без повторного построения: добавляет элементы в множества, дописывает попытку в список студента, обновляет лучший результат и увеличивает счетчик. После добавления записей `('daria', 'lab_02', 4)` и `('anna', 'lab_02', 3)` студентов, сдавших обе работы, становится трое, а для пары `(anna, lab_02)` лучший результат остается 5, число попыток – 2. Проверка `assert` подтверждает, что инкрементальное обновление дает тот же результат, что и полное построение.

#### 3.2 Обоснование выбора коллекций

- Множество подходит для хранения уникальных значений: повторное добавление не создает дубликатов, проверка принадлежности выполняется за O(1) в среднем, а пересечение, объединение и разность выражаются операциями над множествами.
- Кортеж можно использовать как ключ словаря, так как он неизменяем и хешируем (если хешируемы его элементы): хеш вычисляется по содержимому и не меняется за время жизни ключа.
- Список нельзя использовать как ключ: он изменяем, после изменения его хеш должен был бы измениться, и ключ был бы потерян в таблице; поэтому Python выбрасывает `TypeError: unhashable type: 'list'`.
- Словарь предпочтительнее списка для частого поиска по составному ключу: результат пары `(student, lab)` находится за O(1) в среднем, тогда как в списке кортежей пришлось бы просматривать все записи за O(n).

**Таблица 5 – Средняя сложность операций коллекций**

| Коллекция | Добавление | Поиск | Примечание |
|---|---|---|---|
| set | O(1) | O(1) (проверка принадлежности) | пересечение O(min(\|A\|, \|B\|)) |
| dict | O(1) | O(1) (по ключу) | ключ должен быть хешируемым; для кортежа-ключа хеш считается за O(длина кортежа) |
| list | O(1) в конец (амортизированно) | O(n) (поиск значения), O(1) (по индексу) | вставка в начало O(n) |
| tuple | не изменяется | O(n) (поиск значения), O(1) (по индексу) | хешируем при хешируемых элементах |

Построение всех структур для m записей занимает O(m) времени и O(m) памяти; добавление одной записи – O(1) в среднем.

#### 3.3 Практическое расширение: текстовые запросы

Функция `run_query` разбивает строку на части методом `split()` и выбирает операцию конструкцией `match` с шаблонами последовательностей: `["student", name]`, `["best", name, lab]`, `["attempts", name, lab]`, `["completed", lab]`. Перед обращением к словарям выполняется проверка наличия ключа, поэтому отсутствующая пара, неизвестная команда, команда с неверным числом аргументов и пустая строка обрабатываются сообщением без аварийного завершения.



#### 3.4 Вывод

Выбор коллекции определяется операциями: уникальность и проверка принадлежности – множество, поиск по составному ключу – словарь с кортежем в качестве ключа, хранение упорядоченных попыток – список. Хранение нескольких представлений одних данных (лучший результат, число попыток) ускоряет запросы за счет памяти.

В программе объявлено глобальное имя `course`, внешняя функция `outer` с локальным счетчиком `counter` и вложенная функция `inner`, которая изменяет `counter` через `nonlocal`. Глобальное имя не изменяется: после вызова оно сохраняет прежнее значение. 



**Таблица 6 – Поиск имен во вложенной функции inner**

| Имя | Где найдено | Порядок поиска |
|---|---|---|
| local_note | локальная область (L) функции inner | найдено сразу в L |

#### 4.3 Изменяемое значение по умолчанию

В функции `add_result(value, results=[])` значение по умолчанию вычисляется один раз – при выполнении инструкции `def`, – а не при каждом вызове. Созданный список хранится в `add_result.__defaults__` и живет столько же, сколько функция. Каждый вызов без второго аргумента получает один и тот же объект, поэтому `append` накапливает значения: три вызова с числами 1, 2, 3 возвращают `[1, 2, 3]` каждый (в демонстрации это одна и та же ссылка на список). Исправление – значение по умолчанию `None` и создание нового списка внутри функции:

```text
def add_result(value, results=None):
    if results is None:
        results = []
    results.append(value)
    return results
```

Исправленная версия возвращает `[1]`, `[2]`, `[3]`.

Две проверки с порогами 3 и 5 независимы: каждый вызов фабрики создает новую область видимости и новую ячейку замыкания (`easy.__closure__[0].cell_contents` равно 3, `strict.__closure__[0].cell_contents` – 5).

| Функция | Допустимые входные данные | Результат | Особые случаи |

| minimum(values) | непустой список чисел | наименьшее значение без `min()` | пустой список – `ValueError` |

Правило для студента с пустым списком результатов выбрано заранее: он учитывается в числе студентов группы, но не участвует в среднем, категориях, лидерах и рейтинге, так как среднее для пустого списка не определено. Общий средний результат группы – среднее всех отдельных результатов (а не среднее средних), чтобы студент с большим числом работ вносил пропорциональный вклад. Исходный словарь `students` не изменяется: функции только читают данные и строят новые структуры; рейтинг формируется собственной сортировкой вставками на копии списка итогов.

#### 5.3 Сложность

Пусть M – число студентов, N – общее число результатов. Функции `mean`, `minimum` и `maximum` выполняют один проход по списку студента, поэтому построение итогов всех студентов занимает O(N). Общая статистика группы (`group_summary`) дополнительно один раз проходит по всем результатам и по итогам студентов: O(N + M), то есть O(N) при хотя бы одном результате на студента. Дополнительная память – O(M) (словари итогов). Рейтинг сортировкой вставками требует O(M²) времени в худшем случае; для учебной группы это приемлемо.
